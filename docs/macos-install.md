# Mac 本地应用

SwiftUI / WKWebView 保留现有看板，任务、验证、验收、用量和历史由同一台 Mac 的后台维护。iOS 与手机网关暂缓；手机后续作为 Mac 的镜像控制端，不在手机运行 AI。

## 构建与安装

预构建版本见 [Mac 预发布](https://github.com/Mu-Miao/HelmDesk/releases/tag/v0.1.0-macos-preview.1)。下载 arm64 DMG，打开后将 `HelmDesk.app` 拖到 Applications，再从应用目录启动；ZIP 可直接解压得到同一应用。预构建包内置 Node 和依赖，不需要安装源码工具链。校验值见 Release 附件 `SHA256SUMS`。

**此预发布没有 Developer ID 正式签名或 Apple 公证。** 应用仅有 ad-hoc 本地签名，DMG 本身未签名，macOS 可能阻止首次打开；不能把本地签名完整性检查当作 Gatekeeper 信任或公证通过。正式签名公证仍待办。

本机已验证 Apple Silicon。部署目标 macOS 14+，尚未在最低系统或 Intel 设备实测。源码构建需要 Swift 6 工具链、macOS SDK、Git、Node.js 24.15.0 和 npm。Qoder 官方 CLI/App、登录及项目工具链仍为外部前提。

```sh
npm ci --ignore-scripts
./script/build_and_run.sh --verify
./script/install_macos.sh
./script/distribute_macos.sh --skip-build
```

产物为 `dist/HelmDesk.app`，安装到 `~/Applications/HelmDesk.app`，日常双击无需终端运行 npm 或另装 Node。旧同标识应用保留在 `~/Library/Application Support/HelmDesk-AppBackups/`，不同标识的同名应用会拒绝替换。安装不移动数据库和工作区。

本地分发目录 `dist/releases/HelmDesk-<版本>-macos-<实际架构>-local/` 包含 DMG、ZIP、校验清单、安装说明和组件清单。DMG 提供应用、Applications 快捷入口与本说明。Node 版本与许可锁定；依赖原始许可随生产包保留。包审计拒绝个人配置、越界链接和清单外资源。

当前使用 ad-hoc 本地签名，GitHub 以未签名、未公证的预发布形式提供下载，正式 Developer ID 签名、公证仍待办。构建缓存默认在工作区专属的 `~/Library/Caches/HelmDesk/SwiftPM/`，可用 `HELMDESK_SWIFT_SCRATCH_PATH` 覆盖。Desktop 测试链接曾卡在系统扩展属性读取，本机模块测试使用相同源码临时副本；未完成的命令不计通过。

## 原生设置

首次双击默认使用 `~/Library/Application Support/HelmDesk`；开发脚本默认使用仓库 `.helmdesk`，可用 `HELMDESK_DATA_DIR` 指定。成功连接后记住目录，也可在“连接”页选择旧目录。受保护目录须确认 macOS 文件夹权限。

“执行与数据”页提供官方 Qoder 路径选择或自动发现、项目目录授权、默认模型与思考深度、首选端口、空闲重启、运行诊断和备份。项目范围须明确保存，拒绝系统根、整个主目录与凭据目录；有排队或运行任务时拒绝改执行设置或重启。原生管理接口需要私有本机身份，网页会话无权调用，没有通用网页到 Shell 的桥接。

端口冲突时，未连接页面仍可选择 1024–65535 的其他启动端口；不会按端口杀进程。已有连接先核对身份，应用和 MCP 共用启动锁。

模型目录可列出不等于额度充足，登录文件存在不等于登录有效。诊断不请求推理；不支持的模型与深度会明确拒绝，不静默回退。保存的默认值仅影响后续任务。

## 数据、备份与回滚

优先复用旧目录，不搬动含绝对路径的 Git worktree。身份使用 POSIX 真实路径，避免 `/private/var` 与 `/var` 的别名误判。SQLite schema 为 3；未来版本或缺失关键表在写入前拒绝。兼容旧版本升级在事务中进行，之前用一致性快照保留 `schema-backups/`。

“创建一致性备份”使用 SQLite backup API，包含已提交 WAL 内容，在当前数据目录 `backups/` 下保存私有数据库和清单。清单含 SHA256、任务/事件数量、记录摘要和工作区缺失数量；可选择最近 20 份并校验。

**数据库备份不包含工作区。** 工作区保持原路径，不提供自动覆盖式恢复。可选择保留的旧应用包回滚程序；恢复数据库前应停止相关入口并核对新增记录。存在新任务或新交付时不能直接覆盖旧备份，应先保留现库和工作区再评估恢复。不要复制仍有 WAL 写入的单个数据库文件。

验证绑定具体交付版本，接受、输入交接、依赖放行和整合会检查当前证据。旧验收事实保留，再次整合或交接前旧证据须由宿主重新验证。报告阅读不会自动接受或写回原项目。

## MCP 与导出

设置可导出 `helmdesk-mcp.toml`，供检查后手动合入宿主配置，不自动覆盖。片段指向当前应用内 Node/CLI 和数据目录，按需复用服务；升级保持安装路径不变。原有 28 项 MCP 工具继续可用。

“文件 → 导出任务报告”提供原生分页列表，保存 Markdown / JSON，保留执行、验证版本、验收、用量与失败。看板整合面板仍负责文件选择、只读预检和补丁导出。保存取消不删除目标原文件，限制 20 MB，完成后原子保存。

共享任务表每页最多渲染 50 条，搜索筛选覆盖全部记录，筛选变化回第一页并可定位当前任务。长差异按文件折叠；减少动态效果或 WebGPU 不可用时使用静态背景。

## 生命周期、诊断与验证

关窗或退出界面保留独立后台与任务。异常中断和系统重启留下的运行记录标为待核实，不凭旧 PID 操作进程，也不自动重派。应用接入休眠/唤醒通知，唤醒时重新握手；真实整机休眠另行实测。

错误区分端口、数据不兼容、权限、执行器、沙箱和清理未确认。界面不显示令牌或原始日志；详细现场在本机数据目录。卸载应用不删除数据，需要保留数据时不要删除 Application Support 或旧 `.helmdesk`。

已实际验证安装窗口、原生设置、升级记录一致、备份校验、模型目录与无推理诊断、MCP 真实握手、换端口与冲突恢复、断线重连、菜单 JSON 与 WebKit 补丁保存。真实 Qoder 使用自定义 Max，宿主审核和测试；失败事实保留。CI 已配置，本地通过不代表远端运行通过。正式公证、异机/Intel、最低系统和整机休眠均不计为已验收。完整证据保留在本机私有数据目录。

网页访问由应用签发 60 秒、仅可交换一次的入口票据；票据放在 URL fragment，页面读取后立即清除。点击应用“浏览器”会为该浏览器重新生成入口，不复用原生窗口已使用的票据。永久服务令牌不进入网页。直接输入端口地址不会建立新会话；源码用户可在交互终端运行 `node dist/cli.js browser --data-dir .helmdesk`。服务重启后须从应用重新打开，普通页面刷新仍可复用有效会话。

交换后的网页凭据只保存在该来源的 `sessionStorage`（存储不可用时仅保存在页面内存），通过显式请求头用于 API 和实时事件，不使用 Cookie 认证。不同端口之间不会自动携带凭据。网页会话最长 12 小时，关闭标签页或会话失效后，从应用重新打开；原生管理仍单独要求私有服务身份。
