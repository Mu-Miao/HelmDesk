# HelmDesk v0.1 日常使用与验收手册

适用范围：本机单用户日常使用。仅覆盖下方已验证的接口事实，未实现的特性不做承诺。执行者仅开放受限文件工具，没有 Shell 与子代理；宿主可运行下文的终端验证命令，并负责明确整合。不自动安装其他 CLI、下载模型或打开外链。

## 1. 前置条件

- macOS，Node 24 及以上。
- 已完成官方 Qoder 登录；除该登录外无需其他凭据，不建议引入 API key。
- 在工作副本或干净的 Git worktree 中操作；原始目录在宿主显式整合前保持不变。

## 2. 启动服务

首次构建：

```
npm ci
npm run check
npm test
npm run build
```

启动已有本地服务：

```
node dist/cli.js serve --data-dir .helmdesk --concurrency 2
```

服务仅监听 `127.0.0.1:4317`，不对外提供访问。

## 3. 宿主注册（可选）

```
node scripts/register-codex-mcp.mjs --apply
```

MCP 启动参数：`--data-dir <绝对路径> --autostart-service --concurrency 2`。
已存在的 stdio 客户端需要重连，才能刷新到新工具列表。

## 4. 提交任务

由 Codex 选择 `task_submit`，字段取值：

- `agent`：`qoder-cn`
- `model`：`Qwen3.8-Flash`，`reasoningEffort`：`xhigh`
- `mode`：`files`，并显式给出 `allowedFiles`
- `projectPath`：任务根目录
- `acceptanceCriteria`、`dependencies`
- `timeoutSeconds`：10~600；`maxTurns`：可选，1~100

Worker 只能使用 Read / Write / Edit / Glob / Grep；没有 Shell，也没有 worker 子代理。

## 5. 查看与监控

- 优先用 `task_briefs_list`（limit 10）与 `task_brief_get` 取背景。
- `tasks_watch` 支持 1~8 个目标，每项提供 `taskId` 与上次已知版本号，`timeoutMs` 不超过 55000。
- 返回空 `items` 或 `timedOut` 不表示失败。
- summary 可能被截断，不能替代完整的 `task_get`、`task_events` 与文件审阅。
- 各类 code 不会触发自动重试，也不会静默切换模型。

## 6. 验证与验收

执行、验证、验收三件事分开：

1. 宿主在隔离环境、Worker 之外运行 `npm run check` 与测试。
2. 依据证据调用 `task_verify`（passed / failed）。
3. 再调用 `task_review`（accepted / changes_requested）。

完成（Completed）不等于已验证，也不等于已验收。

整合流程：

- `task_integration_check` 选取已验收的变更路径，并对照原始基线检查。
- `task_patch_export` 使用上一步返回的 fingerprint。
- 补丁由宿主显式审阅后应用。

出现冲突或过期预览被拒绝是预期行为：不强制覆盖，不自动合并。

## 7. 故障恢复

- 先用 `queue_get` 查看队列状态。
- 服务中断后，不要重放仍在运行的请求。
- 先确认进程状态，再决定取消旧任务或显式新建任务。
- `task_cancel` 会保留工作区与历史；不要通过删除数据库或凭据来"修复"状态显示。
- `.helmdesk` 属私有数据，不要放入源码分享。

## 8. 使用边界

- 历史失败的探测记录与原有缺陷交付保留为证据，不得标记为成功。
- 自定义模型使用各自供应商配置；失败时保留原始结果，不自动替换为同名平台模型。
- Ollama 仅为本地安装的单轮、无工具运行；无文件操作、下载、Skills、MCP，不能替代 Qoder。
- Credits 阈值只阻止后续请求，不会限制已经在途的成本。
- 未知取值按未知处理，不当作零。

## 9. 验收清单

- [ ] 四条构建校验命令在隔离环境通过
- [ ] 服务仅在 `127.0.0.1:4317` 可达
- [ ] `task_submit` 字段与取值范围一致
- [ ] Worker 仅使用五个被允许的文件工具，无 Shell、无子代理
- [ ] `tasks_watch` 多目标与超时行为符合预期（空结果与超时不误判为失败）
- [ ] `task_verify` 与 `task_review` 由宿主独立执行，且有证据
- [ ] `task_integration_check` → `task_patch_export`（同 fingerprint）→ 宿主显式应用
- [ ] 冲突或过期预览按预期拒绝，未发生强制覆盖或自动合并
- [ ] `task_cancel` 后工作区与历史仍在，数据库与凭据未被删除
- [ ] `.helmdesk` 未进入源码分享

## 10. 不支持的范围

以下均未实现：远程或公网访问、自动合并与自动发布、无人值守续跑、Claude 与 Gemini 适配器。
本手册不声称安全性已通过认证，也不声称零漏洞。
