# 安装、宿主前提与本地验证

## 宿主前提

- macOS 上的 HelmDesk 后台服务或 Mac 应用可正常运行；Qoder CN 官方 CLI 已安装并登录。HelmDesk 复用现有 CLI 登录，不要求另填模型 API Key；模型是否可调用、额度是否充足仍以官方 CLI 为准。
- 宿主必须支持本地 MCP，并具备在已授权项目范围内读取文件、运行检查命令的能力。HelmDesk 的沙箱和文件门禁仍然生效，Skill 只指导宿主流程，不能替代真实隔离。
- 源码方式还需要 Git、Node.js 24+ 和已完成构建；Mac 应用方式优先使用应用内自带运行时。

## 接入 MCP 与安装 Skill

1. 优先使用已安装 Mac 应用设置中的 MCP 配置导出，检查后合入宿主配置。应用导出指向当前应用内 CLI 和数据目录。
2. 源码方式参考 [../assets/codex-mcp.toml.example](../assets/codex-mcp.toml.example)，把 `/absolute/path/...` 换成真实绝对路径。`command`、`cwd`、`args` 中的 `dist/cli.js` 与 `--data-dir` 必须属于同一份安装。
3. **应用/服务入口与 MCP 必须使用同一数据目录**，否则连不到同一后台。不要为了接入 MCP 另起一套数据目录或重复启动服务。
4. 按现有服务保留并发与默认偏好。模板默认不额外设置并发；如现有服务已配置 1 或 2 个槽位，保持原值，不要因安装 Skill 改变运行中的服务、主要执行器或模型偏好。
5. 按宿主支持的方式加载整个 `helmdesk-workflow` 目录，保留包内相对结构。仅在安装任务已授权时写入相应技能目录；不要顺带改写宿主配置、记忆或安装其他插件。这个 Skill 用于宿主编排，不加入执行者的共享能力。
6. 连接后以 `queue_get`、`agents_list`、`model_preference_get` 只读确认环境；需要核对可用模型或共享能力时再读对应目录。工具名以当前连接 schema 为准，宿主可能显示命名空间前缀。

## 离线审查门禁

在发起任何真实任务前，由宿主离线检查：

- `SKILL.md` 的 `name` 为 `helmdesk-workflow`，description 的触发范围正确：仅用于 HelmDesk 调度与验收，不覆盖泛泛代码修改或纯看板样式。
- 两个 reference 的链接可解析；示例中的工具名、字段和状态值与当前 HelmDesk schema 一致。
- 所有路径仍是占位，没有真实用户名、私人路径、任务编号或凭据；没有把示例输出当成已执行证据。
- 明确区分执行、验证、验收；没有承诺免费调用、token 节省或自动合并发布。

未通过离线审查时先修正文档，不进入真实派发。

## 自包含本地验证

以下步骤由宿主在用户已授权的根目录内执行。它们是验证本 Skill 是否可用的流程，不改变 HelmDesk 门禁。

1. **准备独立演示仓库**：在已授权根下新建干净目录，初始化为 Git 仓库并提交一个 `README.md`，保存其原始字节、HEAD 与干净状态。不要在原项目工作区中清理、丢弃或提交用户的未完成改动；原项目 dirty 时保持原样，改用新演示仓库。一般文件任务也支持非 Git 副本，本演示只验证 Git 路径。
2. **只读预检**：调用 `queue_get` 查看槽位和阻塞，`model_preference_get` 确认保存的默认模型；需要时用 `models_list` 核对。示例显式关闭共享，无须刷新共享目录。此步不发起模型请求。
3. **真实、仅一次请求**：按 [tool-examples.md](tool-examples.md) 提交一个 `HELLO.md` 文件任务。使用保存的默认模型和思考深度，`mode: "files"`，`allowedFiles` 仅 `HELLO.md`，验收条件逐字可核对。不要自动重试，也不要换执行器、模型或凭据。
4. **紧凑等待**：用 `task_brief_get` 取版本，再用 `tasks_watch` 携带版本等待。超时无变化只表示等待窗口结束；继续等待同一任务，不重新提交。
5. **宿主独立验证**：`task_get` 后读取隔离工作区中的完整 `HELLO.md`，核对两行内容、`changes` 范围和哈希。运行宿主可用的文件/命令检查，并确认原演示仓库 `git status --porcelain` 仍为空、原目录没有 `HELLO.md`。
6. **记录验证与验收**：依据真实输出调用 `task_verify`。通过才记 `passed`，失败记 `failed` 并保留问题；只有当前版本 `completed` 且 `passed` 时才可 `task_review` 为 `accepted`。`not_run` 不能直接接受。
7. **报告**：分别写明执行结果、验证命令与证据、验收结论、未执行的检查、工具连接问题、用量与未知项。零或缺失用量不解释为免费。未授权整合时，只报告可审阅交付，不应用补丁、不合并、不发布。

## 费用与失败

- 本 Skill 免费，不代表模型调用免费。Qoder 执行消耗其账号额度，宿主自身的拆解、阅读与审核也消耗宿主模型额度；是否节省取决于上下文和返工，不作固定比例承诺。
- 遇到工具缺失、登录失效、模型不可用或隔离失败：记录实际错误，不伪造派发或验证结果，不自动重试，不自动切换执行器、模型或凭据。
- 执行、验证、验收三者必须分开记录；没有真实执行、真实检查和明确接受时，不得合并表述为“已完成并验收”。
